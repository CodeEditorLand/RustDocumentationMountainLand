1//! # AirClient
2//!
3//! gRPC client wrapper for the Air daemon service, providing Mountain with
4//! access to cloud-based backend services including updates, authentication,
5//! file indexing, and system monitoring.
6//!
7//! ## RESPONSIBILITIES
8//!
9//! - **Connection Management**: Manage gRPC connection lifecycle to Air service
10//! - **Service Methods**: Implement all Air service RPC methods
11//! - **Error Translation**: Convert tonic/transport errors to CommonError
12//! - **Connection Retry**: (Optional) Provide automatic retry with backoff
13//! - **Health Checking**: Monitor Air service availability
14//!
15//! ## ARCHITECTURAL ROLE
16//!
17//! AirClient serves as the primary interface between Mountain and the Air
18//! backend service:
19//!
20//! ```
21//! Mountain (Frontend) ──► AirClient ──► gRPC ──► Air Daemon (Backend)
22//! ```
23//!
24//! ### Position in Mountain
25//! - Communication module for Air integration
26//! - Part of the service management layer
27//! - Features-gated behind `AirIntegration` feature flag
28//!
29//! ### Dependencies
30//! - `tonic`: gRPC client framework
31//! - `CommonLibrary::Error::CommonError`: Error handling
32//! - `log`: Structured logging
33//!
34//! ### Dependents
35//! - `AirServiceProvider`: High-level API that wraps AirClient
36//! - `Binary::Service::VineStart`: Initializes Air connection
37//!
38//! ## CONFIGURATION
39//!
40//! - **Default Address**: `[::1]:50053` (configurable via constructor)
41//! - **Transport**: gRPC over TCP/IP with optional TLS
42//! - **Connection Pooling**: (TODO) Implement for multiple concurrent requests
43//!
44//! ## ERROR HANDLING
45//!
46//! All methods return `Result<T, CommonError>` with appropriate error types:
47//! - `IPCError`: gRPC communication failures
48//! - `SerializationError`: Message encoding/decoding failures
49//! - `Unknown`: Uncategorized errors
50//!
51//! ## THREAD SAFETY
52//!
53//! - `AirClient` is `Clone`able and can be shared across threads via `Arc<AirClient>`
54//! - Internal connection state is protected by mutexes (to be implemented)
55//! - All public methods are safe to call from multiple threads
56//!
57//! ## PERFORMANCE CONSIDERATIONS
58//!
59//! - Connection establishment is lazy (deferred until first use)
60//! - (TODO) Implement connection pooling for high-throughput scenarios
61//! - (TODO) Add request caching for frequently accessed data
62//! - (TODO) Implement request timeout configuration
63//!
64//! ## VSCODE REFERENCE
65//!
66//! This implementation borrows patterns from VS Code's extension host and
67//! remote communication:
68//! - `vs/platform/remote/common/remoteAgentConnection.ts` - Connection management
69//! - `vs/platform/remote/common/remoteAgentService.ts` - Service proxy pattern
